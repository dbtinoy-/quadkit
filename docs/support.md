# Support

## Documentation

You are in the right place: start with [Installation](getting-started/installation.md)
and [Your First App](getting-started/first-app.md), or skim the runnable
[feature tour](https://github.com/dbtinoy-/quadkit/tree/main/docs/guides/examples/features) — one feature per file,
each an executable test.

## Bugs and feature requests

Open an issue on the repository using the bug-report or feature-request
template. Include the package versions, your Python version, and a minimal
reproduction — the smallest code that shows the problem.

- [Issue tracker](https://github.com/dbtinoy-/quadkit/issues)
- [Report a bug](https://github.com/dbtinoy-/quadkit/issues/new?template=bug_report.yml)
- [Request a feature](https://github.com/dbtinoy-/quadkit/issues/new?template=feature_request.yml)

## Security vulnerabilities

Do **not** open a public issue for security vulnerabilities. Follow
[SECURITY.md](https://github.com/dbtinoy-/quadkit/blob/main/SECURITY.md) so
the report stays private until a fix ships — see
[Vulnerability reporting](security/vulnerability-reporting.md) for the
process and timelines.

## Contributing

Pull requests are welcome. The development setup, commit format, and DCO
requirements are in
[CONTRIBUTING.md](https://github.com/dbtinoy-/quadkit/blob/main/CONTRIBUTING.md),
and the docs on [contributing](contributing/development.md) cover the same
ground.

## What changed recently

Each release's changes are summarized in the repository
[CHANGELOG.md](https://github.com/dbtinoy-/quadkit/blob/main/CHANGELOG.md).

## Status

Quadkit is alpha software (`0.x`): pin your versions and expect public APIs
to evolve before 1.0. See the [support matrix](reference/support-matrix.md)
for what that means in practice.
